CONDITIONS TO BE PICKED UP BY implementation-planner (Phase 4)
--------------------------------------------------------------------------

1. Element-correlation mechanism (High Risk)
   Define and document the concrete mechanism that correlates a
   DiscoveredElement's BeautifulSoup parse-tree node with its corresponding
   Playwright element handle/locator on rendered pages, so Components 4
   (DOM Parsing & Element Discovery), 5 (XPath Generation), and 6 (Style
   Metadata Extraction) all operate on the same underlying DOM node.
   Example approaches: injected marker attribute (e.g.
   data-locator-lens-id), or a single XPath-derived lookup key computed
   once and reused by both representations.
   -> Must be specified in the Phase 4 task breakdown before Components
      4-6 are implemented in Phase 5.

2. URL-mode size-cap enforcement mechanism (Medium Risk)
   Define and document the concrete Playwright mechanism used to enforce
   the ~5MB response size ceiling during URL-mode navigation/rendering
   (e.g., page.route()/response interception with abort-on-threshold, or
   Content-Length pre-check), replacing the current outcome-only
   description ("streamed byte counting") with a named implementation
   approach.
   -> Must be specified in the Phase 4 task breakdown for Component 3
      (Input Acquisition Module) before implementation in Phase 5.

Both conditions are implementation-detail gaps, not structural defects in
the architecture. They do not require re-submission to design-reviewer
unless resolving them forces a structural change to the components or
data flow described in documents/design-document.md.
